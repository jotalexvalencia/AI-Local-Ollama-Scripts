### 👷‍♂️ Nivel ingeniero de software junior  

| Ítem | Explicación |
|------|-------------|
| **🧠 Concepto (Qué es)** | Script que consulta a un modelo Ollama con capacidad de “thinking” y muestra por separado el proceso de razonamiento y la respuesta final, utilizando streaming HTTP y parsing manual de JSON. |
| **💻 Implementación (Cómo se hace)** | 1. Se definen constantes (URL, modelo, prompt). 2. Se arma un payload JSON con `stream: True` y `num_predict: -1`. 3. Se hace una petición POST con `requests.post(..., stream=True)`. 4. Se itera sobre las líneas de la respuesta, se decodifica cada línea con `json.loads`. 5. Se detectan los campos `thinking` y `content` dentro de `message` y se imprimen en tiempo real, cambiando de fase cuando termina el thinking. 6. Se cuentan palabras en cada bloque y se muestra un resumen. |
| **🔍 Análisis del Código (La Lógica)** | El flujo depende de dos banderas: `in_thinking` y los acumuladores `thinking_content` / `answer_content`. Cada chunk puede contener thinking, content o ninguno. Cuando aparece thinking se marca la fase de razonamiento; cuando aparece content y ya está en thinking se imprime un separador y se pasa a fase de respuesta. Al final se reportan métricas simples de longitud. |
| **✨ Clean Code & Buenas Prácticas (El Estilo)** | - Nombres de función y variables descriptivos. - Comentarios de sección (`# ==========================================`). - Uso de docstrings. - Manejo de excepciones específicas (Timeout, ConnectionError, RequestException, JSONDecodeError). - Evita magic numbers al usar `-1` con comentario. - Se respeta PEP 8 en longitud de líneas y sangrado. |
| **🚀 Aplicación Real / Contexto Empresa** | Utilizado en equipos de MLOps para validar que un modelo desplegado en Ollama realmente exponga su cadena de pensamiento antes de integrarlo en productos que requieran trazabilidad (por ejemplo, sistemas de recomendación explicables o asistencia técnica). |
| **🎯 Oferta donde esto importa** | En contratos de IA responsable donde se exige evidencia de razonamiento interno para auditoría regulatoria o para ofrecer a clientes un modo “show your work”. |
| **🎯 Relevancia para mi ENGRAM** | Fortalece la asociación entre la entrada simbólica (prompt) y los pasos intermedios (thinking), mejorando la codificación procedural en la memoria a largo plazo al requerir que el sujeto siga y registre cada fase del proceso. |
| **🧪 Evidencia que voy a construir (¡OBLIGATORIO!)** | Desarrollaré un script de test que ejecute `app_thinking.py` contra dos modelos, capturará la salida estándar y comprobará que: (a) aparece el separador de thinking → answer, (b) los contadores de palabras son no negativos, (c) no se lanzan excepciones bajo conexión sana. |
| **📌 Nivel real de dominio** | Puedo depurar el script, añadir logging extra, cambiar el parámetro `num_predict` y adaptarlo a otros endpoints sin romper la lógica de detección de thinking. |
| **🎯 Decisión final (¡OBLIGATORIO!)** | **Aprobar** su uso como prototype; para producción recomendaría refactorizar la detección de fases en una función separada y usar tipos más estrictos (TypedDict) para reducir riesgos de clave faltante. |

## 2️⃣ app_thinking_sdk.py  

### 👶 Nivel niño de 5 años  

| Ítem | Explicación |
|------|-------------|
| **🧠 Concepto (Qué es)** | Es otro cuento, pero ahora el robot tiene un ayudante especial (el SDK) que ya sabe cómo leer sus pensamientos y guardar todo en un cuaderno para que no se olvide. |
| **💻 Implementación (Cómo se hace)** | 1. Le decimos al ayudante que anote todo en un archivo llamado `thinking_log.txt`. 2. Le decimos qué robot usar (ornith‑1.5:9b) y qué pregunta hacer. 3. Le pedimos al ayudante que hable con el robot y nos vaya diciendo lo que piensa y luego la respuesta, mientras vamos viendo lo que va diciendo en la pantalla. 4. Cuando el robot deja de pensar, el ayudante guarda lo que pensó en el cuaderno. 5. Al final guarda también la respuesta y nos dice que todo está guardado. |
| **🔍 Análisis del Código (La Lógica)** | Se activa el registro de logs. Se crea una corriente de conversación con `chat(..., think=True, stream=True)`. Cada trozo que llega ya está listo para usar (no hay que convertir texto a JSON). Si trae thinking lo mostramos y lo vamos acumulando. Cuando llega content y ya habíamos visto thinking, imprimimos un separador, guardamos el thinking acumulado en el log y empezamos a acumular la respuesta. Al final guardamos también la respuesta. |
| **✨ Clean Code & Buenas Prácticas (El Estilo)** | Se usa el módulo `logging` para escribir en archivo, se separan claramente las secciones de configuración, llamada al SDK y procesamiento. Los nombres son claros (`thinking_buffer`, `answer_buffer`). |
| **🚀 Aplicación Real / Contexto Empresa** | En una empresa que crea asistentes de voz, este script permite guardar el razonamiento del modelo para revisarlo después y mejorar el producto, tal como un ingeniero revisa los borradores de un diseño antes de lanzar la versión final. |
| **🎯 Oferta donde esto importa** | En productos de IA que ofrecen un modo “show work” a clientes corporativos, donde se necesita un historial auditables del proceso de pensamiento. |
| **🎯 Relevancia para mi ENGRAM** | Al observar cómo el SDK separa thinking y answer y guarda ambos, se refuerza la memoria de trabajo al vincular la entrada (prompt) con dos salidas distintas (razonamiento y respuesta) y se crea un registro externo que ayuda a la consolidación a largo plazo. |
| **🧪 Evidencia que voy a construir (¡OBLIGATORIO!)** | Ejecutaré el script con el modelo ornith‑1.5:9b, revisaré que el archivo `thinking_log.txt` contenga bloques delimitados por `--- INICIO THINKING ---` y `--- FIN THINKING ---` seguidos de bloques de answer, y confirmaré que no haya líneas sueltas fuera de esos bloques. |
| **📌 Nivel real de dominio** | Puedo correr el script, modificar el nivel de logging, cambiar el destino del archivo y añadir campos extra (timestamp, modelo) sin romper el flujo. |
| **🎯 Decisión final (¡OBLIGATORIO!)** | **Aprobar** su uso como ejemplo de cómo aprovechar el SDK oficial para obtener thinking de forma más limpia y con persistencia automática. |

CONFIGURACIÓN DE LOGGING, etc.). <br> - No se usan magic strings sin explicación. |

El log puede ser ingestado por sistemas de SIEM o de análisis de cumplimiento. |
| **🎯 Oferta donde esto importa** | En licencias de IA empresarial que incluyan un módulo de explicabilidad y auditoría; el cliente recibe no solo la respuesta sino también un registro verificable del razonamiento. |
| **🎯 Relevancia para mi ENGRAM** | La acción de guardar explícitamente el thinking y el answer en un archivo externo crea una doble codificación: la información se procesa internamente y se almacena externamente, lo que mejora la probabilidad de recuperación futura y fortalece la memoria semántica relacionada con el proceso de razonamiento del modelo. |
